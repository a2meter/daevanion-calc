# 데바니온 링크

아이온2 클라이언트가 서버에서 받는 패킷을 읽어 내 캐릭터의 데바니온 보드 상태와 스킬 레벨을 알아낸 뒤, 버튼 한 번으로 웹 계산기([데바니온 보드](https://daevanion.a2meter.workers.dev))를 그 상태로 여는 작은 창 프로그램입니다. Windows와 macOS에서 동작합니다.

- 읽는 것: 보드별로 열린 노드, 스킬별 레벨과 데바니온 노드로 오른 레벨, 현재·최고 전투력.
- 보내는 것: 없습니다. 상태는 주소의 `#` 뒤(프래그먼트)에 담아 브라우저에 넘기며, 프래그먼트는 서버로 전송되지 않습니다. 이 프로그램은 네트워크로 아무것도 보내지 않고, 게임 클라이언트나 패킷을 건드리지 않습니다.
- 웹 쪽에서 링크를 읽어 재계산하는 부분은 이 폴더의 범위가 아닙니다. 아래 [페이로드 형식](#페이로드-형식-버전-1)에 맞춰 따로 구현합니다.

## 내려받기

파이썬 없이 실행되는 파일을 [릴리스](https://github.com/a2meter/daevanion-calc/releases/latest)에서 받습니다.

| 운영체제 | 파일 |
| --- | --- |
| Windows (64비트) | [DaevanionLink.exe](https://github.com/a2meter/daevanion-calc/releases/latest/download/DaevanionLink.exe) |
| macOS (Apple Silicon) | [DaevanionLink-macos.zip](https://github.com/a2meter/daevanion-calc/releases/latest/download/DaevanionLink-macos.zip) |

실행 파일은 서명하지 않았습니다. Windows에서 SmartScreen 경고가 나오면 **추가 정보** → **실행**을 누르고, macOS에서 열 수 없다는 경고가 나오면 시스템 설정의 개인정보 보호 및 보안에서 **그래도 열기**를 누릅니다.

## 필요한 것

| 운영체제 | 캡처 방법 | 준비 |
| --- | --- | --- |
| Windows | scapy가 Npcap으로 직접 캡처 | [Npcap](https://npcap.com)을 직접 설치합니다. 없으면 창에 안내만 표시하며, 프로그램이 설치 파일을 내려받지 않습니다. |
| macOS | `tcpdump`의 출력을 읽음 | `tcpdump`는 기본으로 들어 있습니다. 캡처 권한이 없으면 창에 **관리자 권한으로 캡처** 버튼이 나타납니다. |
| Linux | `tcpdump`의 출력을 읽음 | `tcpdump`와 캡처 권한이 필요합니다. 관리자 권한 버튼은 없습니다. |

소스에서 실행하려면 파이썬 3.9 이상과 `link/requirements.txt`의 scapy 2.8.0, lz4 4.4.5가 필요합니다. 창은 표준 라이브러리의 tkinter만 씁니다.

macOS의 Xcode·명령줄 도구에 들어 있는 파이썬(`/usr/bin/python3`)은 Tk 8.5에 연결되어 있고, 이 Tk는 최근 macOS에서 창을 만들기 전에 프로세스를 중단시킵니다(2026-11-13, macOS 15.8에서 확인). 프로그램은 이 경우를 미리 확인해 안내문을 출력하고 종료 코드 1로 끝납니다. 창을 쓰려면 python.org의 파이썬처럼 Tk 8.6 이상이 연결된 파이썬으로 실행하거나, 빌드한 실행 파일을 사용하십시오. `--read`는 Tk 없이도 동작합니다.

## 실행

```sh
python3 -m venv .venv-link
.venv-link/bin/python -m pip install -r link/requirements.txt
.venv-link/bin/python link/daevanion_link.py
```

Windows에서는 `.venv-link\Scripts\python`을 씁니다.

| 명령 | 동작 |
| --- | --- |
| `python link/daevanion_link.py` | 창을 엽니다. |
| `python link/daevanion_link.py --start` | 창을 열면서 바로 캡처를 시작합니다. |
| `python link/daevanion_link.py --interface en0 --site http://localhost:8787` | 처음 고를 인터페이스와 사이트 주소를 지정합니다. |
| `python link/daevanion_link.py --read capture.pcap` | 창 없이 저장한 pcap·pcapng를 읽어 요약과 링크를 출력합니다. 보드 정보나 스킬 목록이 없으면 이유를 표준 오류에 적고 종료 코드 1로 끝납니다. |
| `python link/daevanion_link.py --read capture.pcap --print-link` | 링크만 출력합니다. |
| `python link/daevanion_link.py --decode '<링크 또는 데이터>'` | 링크의 내용을 JSON으로 출력합니다. scapy와 lz4 없이 동작합니다. |

게임 서버 포트가 13328이 아니면 `--port`로 지정합니다.

## 사용 순서

1. **게임에 접속하기 전에** 프로그램을 켜고 **캡처 시작**을 누릅니다. 보드 전체(`0x26E2`)와 스킬 목록(`0x0051`)은 캐릭터가 게임에 들어갈 때만 옵니다. 이미 접속해 있었다면 프로그램을 켜 둔 채로 게임에 다시 접속합니다. 실측한 두 번의 접속은 모두 새 TCP 연결이었고, 캐릭터 선택 화면으로 나갔다 들어오는 것만으로 다시 오는지는 확인하지 못했습니다.
2. 상태 줄이 "보드와 스킬을 모두 읽었습니다"로 바뀌면 **웹에서 재계산**과 **링크 복사**가 켜집니다. 두 가지를 모두 읽기 전에는 꺼져 있고, 무엇을 기다리는지 상태 줄에 표시합니다.
3. 그 뒤로 게임에서 노드를 열거나 닫으면 창의 수치가 따라 바뀝니다. 버튼을 누른 시점의 상태가 링크에 담깁니다.

창에 표시하는 것은 상태 줄, 현재·최고 전투력, 보드별 열린 노드 수(시작 노드 포함. 71~74와 79는 네자칸·지켈·바이젤·트리니엘·루미엘, 그 밖은 "보드 N"), 읽은 스킬 수, 마지막 변경 시각, 인터페이스 선택, 사이트 주소입니다.

- 인터페이스는 기본 경로(0.0.0.0/0)가 나가는 것을 처음에 고릅니다. 알 수 없으면 주소가 있는 첫 인터페이스입니다. VPN을 쓰거나 게임이 다른 인터페이스로 나가면 직접 고르십시오.
- 창에서 바꾼 사이트 주소와 직접 고른 인터페이스는 사용자 설정 폴더의 `DaevanionLink/config.json`에 남깁니다(Windows `%APPDATA%`, macOS `~/Library/Application Support`, Linux `$XDG_CONFIG_HOME` 또는 `~/.config`). `DAEVANION_LINK_CONFIG` 환경 변수로 파일 위치를 바꿀 수 있습니다. `--site`와 `--interface`로 준 값은 그 실행에만 쓰고 남기지 않습니다.
- 사이트 주소는 `http`·`https` 주소만 받습니다.

### macOS의 관리자 권한 캡처

권한 없이 `tcpdump`가 장치를 열지 못하면 **관리자 권한으로 캡처** 버튼이 나타납니다. 누르면 `osascript`의 `do shell script … with administrator privileges`로 `tcpdump`만 관리자 권한으로 실행하고, 암호는 macOS가 띄우는 창이 받습니다. 프로그램은 암호를 받거나 저장하거나 전달하지 않습니다.

관리자 권한으로 도는 것은 아래 한 줄뿐입니다. `tcpdump`는 임시 폴더의 pcap 파일에 쓰고, 프로그램이 그 파일을 따라 읽습니다. 셸은 1초마다 프로그램의 pid와 실행 표시 파일을 확인해, 프로그램이 없어졌거나 **중지**로 표시 파일이 지워졌으면 `tcpdump`를 끝냅니다.

```sh
umask 022; /usr/sbin/tcpdump -n -p -U -s 0 -i en0 -w <임시>/capture.pcap 'tcp src port 13328' >/dev/null 2><임시>/tcpdump.log & T=$!; while kill -0 <pid> 2>/dev/null && kill -0 $T 2>/dev/null && [ -e <임시>/running ]; do sleep 1; done; kill $T 2>/dev/null; wait $T 2>/dev/null; exit 0
```

임시 파일은 캡처하는 동안 계속 커지고(2026-11-13 실측 약 17MB/시간) 캡처를 멈추면 지웁니다.

## 읽는 패킷

모두 서버에서 클라이언트로 오는 TCP 13328번 포트의 스트림입니다. TCP 재조립과 프레임 판독은 `scripts/measure_cp.py`, 데바니온 패킷 판독은 `scripts/watch_daevanion.py`의 코드를 그대로 가져다 씁니다. 패킷 구조의 근거는 [실측 메모](../NOTMETER_PACKET_NOTES.md)에 있습니다.

| 명령 | 내용 | 상태에 반영하는 방식 |
| --- | --- | --- |
| `26 E2` | 접속할 때의 보드 전체 | 보드 상태를 통째로 바꾸고 "보드 완료"로 표시합니다. |
| `28 E2` · `2B E2` | 노드 열기·닫기 응답 | 결과 코드가 0일 때 노드를 넣거나 뺍니다. |
| `03 E5` | 경로 열기 응답 | 결과 코드가 0일 때 목록의 노드를 모두 넣습니다. 이미 열린 노드가 섞여 있어도 됩니다. |
| `2D E2` | 보드 초기화 응답 | 결과 코드가 0일 때 그 보드를 시작 노드(113번)만 남깁니다. |
| `29 E2` | 열림 알림 | 목록의 노드를 넣습니다. |
| `00 51` | 접속할 때의 스킬 목록 | 목록의 스킬을 모두 넣고 "스킬 완료"로 표시합니다. |
| `13 38` | 스킬 레벨 갱신 | 그 번호의 레벨과 데바니온 레벨을 바꿉니다. |
| `56 36` | 전투력 | 현재·최고 전투력을 바꿉니다. |
| `4A 36` | 스탯 갱신 | 링크에는 넣지 않습니다. `--read` 요약에 종류 수만 적습니다. |

변경 하나에 따라오는 패킷의 순서는 클라이언트마다 다르므로 프레임 하나씩 따로 반영하며 순서에 기대지 않습니다. 상태는 TCP 연결별로 따로 두고, 아는 패킷이 마지막으로 온 연결을 창에 보입니다. 게임을 껐다 켜면 새 연결이므로 접속 정보를 다시 받을 때까지 버튼이 꺼집니다.

이어지지 않는 구간이 생기거나 프레임 정렬이 어긋나면 그 사이의 변경을 놓쳤을 수 있으므로 "완료" 표시를 거두고 다시 접속하라고 안내합니다.

### 스킬 목록 `00 51`

2026-11-13 로그인 두 번의 본문(1,412바이트, 두 번이 같았습니다)에서 확인한 구조입니다.

- 바이트 0: 레코드 수(88).
- 레코드: 표시 1바이트, 스킬 번호 u32, 현재 레벨 u8, 직접 올린 레벨 u8, 데바니온 노드로 오른 레벨 u8, 이어서 8바이트. 모두 16바이트입니다.
- 표시가 `0x01`이면 16바이트, `0x05`이면 끝에 1바이트가 더 붙어 17바이트입니다. 실측 목록은 `0x01` 85개, `0x05` 3개였습니다(1 + 85×16 + 3×17 = 1,412).

```
01 eb030000 01 01 00 0000000000000000        번호 1003, 레벨 1, 직접 1, 데바니온 0
01 b09f0401 0e 0a 04 0000000000000000        번호 17080240, 레벨 14, 직접 10, 데바니온 4
05 6ced0401 12 0a 04 0002020000000000 03     번호 17100140, 레벨 18, 직접 10, 데바니온 4 (17바이트)
```

표시가 이 두 값이 아니거나, 레코드 수가 맞지 않거나, 본문 끝에서 정확히 끝나지 않으면 일부만 읽어 넣지 않습니다. 스킬은 완료되지 않은 채로 두고 창에 "스킬 목록을 읽지 못했습니다"라고 표시합니다. 88개 레코드 모두 레벨 뒤 다섯 바이트(직접 올린 레벨, 데바니온 레벨, 그 밖의 가산 셋)의 합이 현재 레벨과 같았습니다.

`boards/skill-ids.json`은 `--read` 요약에 스킬 이름을 붙이는 데만 씁니다. 스킬을 읽는 데는 쓰지 않으며, 파일이 없어도 동작합니다.

### 스킬 레벨 갱신 `13 38`

`watch_daevanion.skill_list`가 읽는 17바이트 항목(스킬 번호 u32, 1바이트, 스킬 번호 u32, 레벨 u8)에서 레벨 뒤의 다섯 바이트도 목록과 같은 뜻으로 읽습니다(직접 올린 레벨, 데바니온 레벨, 그 밖의 가산 셋). 2026-11-13 캡처의 317건 모두 다섯 값의 합이 레벨과 같았고, 데바니온 레벨은 그 시점에 열려 있던 해당 스킬 노드 수와 같았습니다. 합이 맞지 않는 항목은 데바니온 레벨을 0(모름)으로 둡니다.

스킬 하나에 번호가 여럿인 경우가 있습니다(예: 약화의 낙인 17080000, 17080020, 17080240). 실측에서 변형 번호의 갱신은 스킬 레벨이 특정 구간에 있을 때와 그 구간을 막 벗어날 때만 왔습니다(변형이 레벨 구간에 묶여 있는 것으로 보입니다). 그래서 구간을 벗어난 변형 번호에는 예전 값이 남습니다(캡처의 마지막 상태에서 17080020은 레벨 11·데바니온 1, 기본 번호 17080000은 레벨 13·데바니온 3). **스킬의 현재 레벨은 기본 번호(`…0000`)의 값으로 읽으십시오.**

## 페이로드 형식 (버전 1)

주소는 `<사이트>/#link=<데이터>`입니다. 사이트의 기본값은 `https://daevanion.a2meter.workers.dev`입니다. `<데이터>`는 아래 바이트열을 패딩(`=`) 없는 base64url(`+/` 대신 `-_`)로 적은 것입니다. 여러 바이트 값은 모두 리틀 엔디언입니다.

| 위치 | 크기 | 내용 |
| --- | --- | --- |
| 0 | 2 | ASCII `DV` (`44 56`) |
| 2 | 1 | 버전. `1` |
| 3 | 1 | 플래그. 비트 0 = 보드 완료(`26 E2`를 받았음), 비트 1 = 스킬 완료(`00 51`을 읽었음). 나머지 비트는 0으로 쓰고 읽을 때 무시합니다. |
| 4 | 4 | `capturedAt` u32. 이 상태가 유효했던 마지막 시각(그 연결에서 마지막으로 읽은 프레임의 패킷 시각), UNIX 초 |
| 8 | 4 | `power` u32. 현재 전투력. 받지 못했으면 0 |
| 12 | 4 | `bestPower` u32. 최고 전투력. 받지 못했으면 0 |
| 16 | 1 | `boardCount` u8 |
| 17 | 30 × boardCount | 보드. 번호 오름차순. 보드마다 `boardId` u8, 이어서 29바이트 비트맵 |
| … | 1 | `skillCount` u8 |
| … | 6 × skillCount | 스킬. 번호 오름차순. 스킬마다 `skillId` u32, `level` u8, `daevanionLevels` u8 |

- 비트맵: 비트 k(k = 0…224)가 1이면 순번 k+1인 노드가 열려 있습니다. 비트 k는 바이트 `k >> 3`의 `1 << (k & 7)` 자리입니다(바이트 안에서 낮은 비트부터). 노드 번호는 `boardId × 10000 + 순번`, 순번은 `(row − 1) × 15 + col`입니다. 시작 노드(8행 8열, 순번 113)도 열린 노드로 들어 있습니다. 225번째 뒤의 남는 7비트는 0으로 쓰고 읽을 때 무시합니다.
- `boardId`는 패킷의 보드 번호 그대로입니다(이 캐릭터는 71~79). 255를 넘는 번호는 넣지 않습니다. 직업에 따라 번호가 다르며, 웹은 보드 데이터가 있는 71~74와 79만 가져옵니다.
- 스킬은 접속할 때의 목록에 있던 것 전부(실측 88개)와, 그 뒤 `13 38`로 처음 본 번호입니다. 데바니온과 무관한 스킬(번호 1003 같은 공용 스킬)도 들어 있습니다.
- `daevanionLevels`는 `level` 가운데 데바니온 노드로 오른 몫입니다. 0은 "없음" 또는 "모름"입니다. 변형 번호의 값이 오래된 것일 수 있다는 점은 위 [스킬 레벨 갱신](#스킬-레벨-갱신-13-38)을 보십시오.
- 길이는 `18 + 30 × boardCount + 6 × skillCount`바이트이고, 남는 바이트가 있으면 잘못된 데이터입니다. 버전이 1이 아니면 읽지 않습니다.

`link_payload.py`의 `encode(state)`와 `decode(text)`가 기준 구현이며 표준 라이브러리만 씁니다. `decode`는 데이터 문자열과 `#link=`가 든 주소를 모두 받고, 보드와 스킬을 순서대로 담은 dict를 돌려줍니다.

### 주소 길이

주소 전체를 2,000자 미만으로 맞춥니다. 보드 9개·스킬 94개인 2026-11-13 캡처의 마지막 상태는 1,180자였습니다. 2,000자 이상이 될 상황이면 다음 순서로 스킬을 덜어 냅니다.

1. `daevanionLevels`가 0인 스킬을 번호가 큰 것부터 뺍니다.
2. 그래도 넘치면 나머지 스킬을 번호가 큰 것부터 뺍니다.
3. 하나라도 빼면 플래그의 스킬 완료 비트를 0으로 쓰고, 창에 뺀 개수를 알립니다. 보드는 빼지 않습니다.
4. 스킬을 모두 빼도 넘치면(사이트 주소가 지나치게 긴 경우) 링크를 만들지 않고 오류를 표시합니다.

스킬이 255개를 넘는 경우에도 같은 순서로 255개까지만 넣습니다.

## 파일

| 파일 | 내용 |
| --- | --- |
| `daevanion_link.py` | 실행 진입점. 인자 처리와 `--read`, `--decode` |
| `link_payload.py` | 페이로드 `encode`·`decode`·`fit`. 표준 라이브러리만 사용 |
| `link_core.py` | 화면 없는 핵심부. 프레임별 상태 추적(`Tracker`), 연결별 재조립(`Demux`), 저장한 캡처 읽기, 링크·상태 문구·설정 |
| `link_capture.py` | 실시간 캡처. `tcpdump` 실행, 관리자 권한 캡처, scapy 캡처, 인터페이스 목록, 뒤쪽 스레드 |
| `link_gui.py` | tkinter 창. 뒤쪽 스레드가 큐에 넣은 소식을 0.1초마다 꺼내 보여 줍니다. |
| `build.py` | PyInstaller 빌드 |
| `requirements.txt` · `requirements-build.txt` | 실행용, 빌드용 의존성 |

## 빌드

```sh
python -m pip install -r link/requirements.txt -r link/requirements-build.txt
python link/build.py
```

결과는 `link/dist/`에 생깁니다. Windows는 `DaevanionLink.exe` 한 파일, macOS는 `DaevanionLink.app`입니다. 빌드한 운영체제와 CPU용으로만 만들어집니다.

GitHub Actions의 `.github/workflows/link-build.yml`이 같은 명령으로 `windows-latest`와 `macos-latest`에서 빌드해 `DaevanionLink-windows`, `DaevanionLink-macos` 아티팩트로 올립니다. Actions 탭에서 수동으로 실행하거나 `link-v`로 시작하는 태그를 푸시하면 돕니다. 이 워크플로는 빌드 전에 이 폴더의 테스트를 돌리고 창을 한 번 열었다 닫으며, 빌드 뒤에는 실행 파일에 필요한 모듈이 다 들어갔는지 확인합니다.

배포는 태그로 합니다. `link-v0.1.0`처럼 `link-v`로 시작하는 태그를 푸시하면 두 빌드가 모두 성공한 뒤 같은 이름의 릴리스가 만들어지고 `DaevanionLink.exe`와 `DaevanionLink-macos.zip`이 붙습니다. 릴리스 본문은 `link/RELEASE_NOTES.md`입니다. macOS 빌드는 러너의 CPU인 Apple Silicon용만 만들어지며, 실행 파일은 서명하지 않습니다.

## 한계와 확인하지 못한 것

- 캐릭터가 게임에 들어갈 때 프로그램이 캡처 중이어야 합니다. 중간에 시작하면 그 뒤의 변경만 보이고 버튼은 켜지지 않습니다.
- 패킷 구조는 2026-11-13 캡처 하나(한 캐릭터, 한 직업, macOS의 PlayCover 클라이언트)에서 확인했습니다. 클라이언트가 패치되어 구조나 명령 번호가 바뀌면 읽지 못합니다. 스킬 목록은 구조가 맞지 않으면 읽지 않고 그 사실을 표시합니다.
- 스킬 변형 번호의 값은 오래된 것일 수 있습니다(위 설명).
- 같은 PC에서 게임 연결이 여러 개이면 아는 패킷이 마지막으로 온 연결을 보입니다.
- Windows의 실제 캡처(Npcap)와 macOS의 관리자 권한 요청 창을 거친 캡처는 이 저장소 작업 중에 실행해 보지 못했습니다. Windows 캡처 경로는 저장한 pcap을 같은 코드에 넣어 보는 시험만 있고, 관리자 권한 경로는 권한 요청과 `tcpdump`를 대역으로 바꾼 시험만 있습니다.
- 실행 파일은 2026-11-13에 GitHub Actions의 `windows-latest`와 `macos-latest`에서 빌드했습니다. 두 곳 모두 테스트가 통과했고, 실제 창이 열렸으며, 빌드한 실행 파일의 자체 점검(페이로드, lz4, 창)이 통과했습니다. 내려받은 실행 파일을 Windows PC나 다른 Mac에서 직접 실행해 본 기록은 없습니다.
- 실제 창은 Homebrew의 Python 3.11과 Tk 8.6으로 띄워, 캡처 권한이 없을 때의 안내와 관리자 권한 버튼까지 보았습니다.
